## What got built today (chronological)

This was a marathon. Order matters because some fixes depended on others.

1. **Two-stage tagging architecture COMPLETE** (`/do-it` ran the full pipeline yesterday). 4 chunks, ~18 commits. Multi-window extraction (5 windows × 15s each), category-complete negative filtering, Stage 2 judgment layer for Timing tags, per-category thresholds with strictness-as-offset. Spec at `docs/superpowers/specs/2026-06-12-two-stage-tagging-design.md`, plan at `docs/superpowers/plans/2026-06-12-two-stage-tagging.md`.

2. **Descriptive sub-category granularity** (commit `6053675`). The category-complete filter operates at top-level Descriptive, so a track tagged only "Dark, Funky" (Vibes) was counting as a trusted negative for "Walking" (BassType). Fix routes descriptive tags through `DescriptiveTagMapping.effectiveCategory(for:topLevel:)` so BassType/Rhythm/Style/Vibes/Instruments/VocalType each get their own category-complete gate. Custom descriptive tags fall back to top-level "Descriptive". No retrain needed; applies on next training run.

3. **Three sequential field-mapping bugs found and fixed.** This was the day's main thread. The user's stage 2 timing F1 was 2.7% — looked catastrophic. Three layers of silent fallback were eating the data:

   - **TagMappingConfiguration decoder bug** (`9f94de3`). Persisted JSON in UserDefaults had legacy frame-ID suffix format like `"Album Artist (TPE2)"` but current `ID3Field` rawValues are just `"Album Artist"`. JSON decode failed silently via `try?`, fell back to `TagMappingConfiguration.default` (TALB for timing, TIT1 for mood). So training read TALB for Timing despite the user's UI showing Album Artist. Fix: custom `init(from:)` that strips `\s*\([A-Z0-9:]+\)\s*$` regex; `load()` re-saves unconditionally to migrate the blob. Live plist migrated by orchestrator at `~/Library/Containers/com.cratebot.CrateBot/Data/Library/Preferences/com.cratebot.CrateBot.plist`.

   - **Eval script hardcoded wrong frames** (`88ae5b1`). Even after the runtime read TPE2 correctly, `scripts/accuracy_eval.py` hardcoded `Timing → TALB / Mood → TIT1` for ground-truth read — so the eval was measuring Peak/Build/etc predictions against TALB content (which contains Aggressive/Happy/etc, the user's Mood values). Fix: reads field mapping from `~/Library/Application Support/cratebot/lexicon.json` (the runtime source of truth training writes). After fix on existing CB5_v5: **Stage 2 F1 3.4% → 40.1%, combined 48.3% → 50.7%, clears the 45% gate.** Model was healthy all along.

   - **App icon was a white square** (`52dda55`). The PNG assets had a circle on a white square canvas; macOS displays exactly what you give it. Fix: composited the existing logo onto a full-bleed dark squircle with 22.5% corner radius via PIL; regenerated all 10 standard sizes; rebuilt.

## The three Vibe Generator v2 chunks done in detail

### Chunk 1 — TimingPrediction surfaced on TaggingResult (commits `bd9b77f` + fix `a5fc607`)
- New `TimingPrediction { label: String; confidence: Float }` (Sendable, Equatable) at `CrateBotCore/Sources/CrateBotCore/ML/TaggingEngine.swift`.
- `TaggingResult.timingPrediction: TimingPrediction?` with default nil — backwards compatible.
- `judgmentPass` captures argmax label + confidence inside the existing classifier loop; threads through `analyze()`.
- Important: the value is **raw post-sigmoid**, NOT calibrated. Stage 2 models don't carry a `ConfidenceCalibrator` because they were trained on Stage 1's already-calibrated outputs. Docstrings now say "raw post-sigmoid" everywhere. **Do not double-calibrate downstream.**

### Chunk 2 — Cooccurrence + Inputs (commits `25119d2` + `2111855` + fix `138f347`)
- `CooccurrenceContext.swift` (Integrations/) — Stats struct with snake_case CodingKeys → camelCase Swift props (`baseRates`/`totalTracks`). `loadFromBundle()` reads `tag_cooccurrence.json` from Resources; logs decode failures, silent on missing file. `Cooccurrence.context(timing:stats:topK:minSupport:minLift:)` returns top-K co-occurring tags by lift; nil when row missing/empty/thin OR no surviving tags. NEVER throws.
- `VibeGenerationInputs.swift` — value type carrying Stage 1 confidences + multi-class group probs + predicted tags + bpm/key/duration + title/artist + stage2Timing + cooccurrence. `promptPayload() -> String` emits deterministic sorted-keys JSON. All Float values rounded to 3dp THROUGH `round3` which also sanitizes NaN/Inf to 0.0. Numbers stored as Double in the wire Payload to avoid Float→Double promotion noise. **This is the single source of truth for what the LLM sees.**

### Chunk 3 — VibeGeneratorV2 actor (commits `85d50c4` + fix `69f20cc` + polish `d5355fa`)
- `VibeGeneratorV2.swift` (Integrations/) — actor + `VibeChatClient` protocol + `VibeGeneratorError` + `VibeGenerationResult`.
- Strict JSON parsing: `stripFences` → `extractFirstJSONObject` (string-aware brace counter, handles escaped quotes per the polish commit) → JSONDecoder. Empty short/long → parse failure. **Never falls back to raw text** — that was the legacy CrateBot4 bug.
- Mix-hint gate: `inputs.stage2Timing?.confidence ?? 0 > 0.5 AND inputs.cooccurrence != nil`. Closed gate strips mix-hint instructions from prompt AND forces result mixHint nil.
- `AnthropicVibeChatClient` adapter threads `temperature: 0.7` through `MessageRequest.temperature: Double?` (added in the chunk 3 fix). Round-trip test asserts JSON contains `"temperature": 0.7`. Original BLOCKER: temperature was being silently dropped because MessageRequest had no field — caught by both reviewers.
- `NativeVibeGenerator` marked `@available(*, deprecated, message: "Use VibeGeneratorV2")`. NativeVibeGeneratorTests class marked `@available(*, deprecated)` too, to suppress warning spam.
